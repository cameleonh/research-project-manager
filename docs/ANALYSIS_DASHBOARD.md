# Optional Analysis Dashboard

`ANALYSIS_DASHBOARD.md`는 분석이 많은 논문에서만 쓰는 선택 파일이다. 기본 템플릿에 항상 넣지 않는다. 분석 스크립트, 결과 폴더, 원고 위치가 늘어나서 `FILES.md`만으로 관계를 추적하기 어려울 때 만든다.

## 언제 만드는가

다음 중 하나에 해당하면 만든다.

- 분석 스크립트가 3개 이상이다.
- 결과 폴더가 여러 개다.
- baseline, main analysis, robustness, benchmark가 나뉜다.
- 여러 모형을 비교한다.
- 원고 결과장이 어떤 분석에서 왔는지 헷갈리기 시작했다.

## 언제 만들지 않는가

다음 경우에는 만들지 않는다.

- 분석 1개짜리 단순 논문이다.
- 아직 아이디어 또는 연구계획 단계다.
- 코드 없이 원고 중심으로 진행되는 논문이다.
- `FILES.md`만으로도 충분히 추적 가능하다.

## 권장 위치

프로젝트 루트에 둔다.

```text
paper_project/
  START_HERE.md
  WBS.md
  FILES.md
  ANALYSIS_DASHBOARD.md
  04_analysis/
  06_manuscript/
  07_outputs/
```

`START_HERE.md`에는 다음처럼 연결한다.

```markdown
분석 코드와 결과 폴더 관계는 `ANALYSIS_DASHBOARD.md`를 본다.
```

## ID 규칙

권장 ID는 `A0`, `A1`, `A2`처럼 단순하게 둔다.

- `A0`: pilot, smoke test, 참고용 분석
- `A1`: EDA 또는 자료 확인
- `A2`: baseline
- `A3`: main analysis
- `A4`: benchmark 또는 robustness

프로젝트 성격에 따라 `R1`, `B1`, `S1`처럼 바꿔도 되지만, 한 프로젝트 안에서는 규칙을 바꾸지 않는다.

## 상태값

상태값은 단순하게 유지한다.

- 계획
- 실행중
- 완료
- 검증필요
- 원고반영
- 보류

`완료`는 코드가 실행됐다는 뜻이고, `원고반영`은 결과가 원고 문장과 표/그림에 반영됐다는 뜻이다. 둘을 구분해야 한다.

## FILES.md와의 차이

`FILES.md`는 핵심 파일 위치를 찾기 위한 목록이다. `ANALYSIS_DASHBOARD.md`는 분석 ID별로 왜 그 분석이 존재하는지, 어떤 주장을 지원하는지, 원고 어디에 들어가는지를 연결한다.

한 줄로 정리하면 다음과 같다.

- `FILES.md`: 어디에 있는가
- `ANALYSIS_DASHBOARD.md`: 왜 있고, 어디에 쓰이는가
