# Architecture: Server WSL + Local Windows Agent

## Core Decision

Server WSL cannot directly show notifications in the currently active local Windows notification center. Therefore, local notifications must be generated by a process running on the local Windows machine.

The architecture uses three layers:

```text
Server WSL
  owns repo updates and optional automation

Shared Markdown Storage
  owns project data and reminder rows

Local Windows Agent
  owns visible Windows notifications and local scheduled scans
```

## Data Ownership

| Data | Owner | Notes |
|---|---|---|
| Project status | `PROJECT_DASHBOARD.md` | Canonical |
| Reminder rows | `PROJECT_DASHBOARD.md` | Canonical |
| Paper project details | project Markdown folder | Canonical |
| Notification state | `.research_pm_state/reminders.json` | Local or shared, depending on deployment |
| Google event IDs | `.research_pm_state/reminders.json` | Generated output state |
| Outlook event IDs | `.research_pm_state/reminders.json` | Generated output state |
| OAuth tokens | user config directory | Never commit |

## Notification Flow

```text
1. Local Windows Task Scheduler starts daily.
2. Task runs .research_pm_tools/cli.js.
3. CLI reads PROJECT_DASHBOARD.md from shared Research_HQ.
4. CLI parses project rows, collaboration waits, and reminder queue.
5. CLI compares due items with .research_pm_state/reminders.json.
6. CLI calls show_windows_notification.ps1 for due items.
7. CLI updates local state to suppress repeats.
```

## Calendar Sync Flow

```text
1. User authenticates Google or Outlook on a machine.
2. CLI reads reminder queue rows where calendar registration is enabled.
3. CLI creates or updates calendar events.
4. CLI stores provider event IDs in .research_pm_state/reminders.json.
5. Calendar apps deliver phone/desktop notifications.
```

## Why Not Server-Pushed Toasts?

Windows toast notifications are local OS UI events. A server-side WSL process does not have the active notification session of the user's current local PC. Sending a Windows toast to the user's current machine would require one of:

- a local agent running on that machine
- a remote push notification service
- calendar or messaging provider delivery

The chosen v1 design uses the local agent because it is the simplest and keeps project data in Markdown.

## Shared Storage Options

### OneDrive

Best when the user already works in OneDrive. Local Task Scheduler reads the local synced folder.

Risk: sync delay.

### SMB / UNC Share

Best when a server exposes a stable network share.

Risk: scheduled task may fail if the share is unavailable or credentials are missing.

### Syncthing

Best for peer-to-peer sync across multiple machines.

Risk: requires separate setup and sync conflict handling.

### Git Pull Per Machine

Best for template/code updates, not ideal for live project dashboard updates unless the user is disciplined.

Risk: merge conflicts and stale local copies.

## Per-Machine vs Shared State

### Per-Machine State

Each Windows PC has its own `.research_pm_state`.

Pros:

- each PC can notify independently
- no state conflicts

Cons:

- same reminder may notify on multiple PCs

### Shared State

All PCs share `.research_pm_state` in the Research HQ folder.

Pros:

- fewer duplicate notifications across machines

Cons:

- state write conflicts are possible
- one PC can suppress reminders on another PC

Recommendation for v1: per-machine state is safer for multi-PC use. If `.research_pm_state` remains in shared storage, document that notifications are shared-state.

## Security Boundaries

- OAuth tokens must not live in the repo.
- OAuth tokens should live in the OS user config directory.
- `.research_pm_state` should not contain client secrets.
- The Codex skill should contain rules only, not project data or credentials.
- Calendar sync should require explicit auth commands.

## Future App Architecture

A future installable app should preserve the same data model:

```text
Markdown parser
Reminder state manager
Windows notification adapter
Calendar sync adapters
Settings UI
Tray UI
```

The GUI must not replace Markdown as source of truth.
